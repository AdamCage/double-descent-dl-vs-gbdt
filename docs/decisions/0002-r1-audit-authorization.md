# Решение 0002 — разрешить ограниченный R1

Дата: 2026-11-07. Автор решения: Codex, научный маршрут проекта.
Статус: конкретизация R1 в рамках [общего мандата](0003-cursor-autonomous-research.md).
Это не одобрение эмпирических выводов и не подтверждающий эксперимент. R2–R7
готовятся и активируются Cursor самостоятельно по общему мандату после зависимостей.
Машинная запись: `research/decisions/R1-authorization.json`; предмет решения:
`research/stages/R1/TASK-CONTRACT.json`.

## Решение и научный вопрос

R0 закрыт. Повторять его исполнение или изменять frozen evidence не требуется.
Разрешаю Cursor подготовить, реализовать, исполнить и операционно закрыть R1:
**какие утверждения поддерживаются унаследованными артефактами и первичными
работами; какие допущения и пробелы необходимо учесть в контролируемом R2?**

R1 — описательный аудит уже доступных результатов и источников. Он не измеряет
новый эффект double descent и не является preregistration будущего эксперимента.
Чтение источников и исходных артефактов до machine freeze допустимо и заносится
в exposure/preparation log. Ретроспективный аудит не переименовывается в confirmation.

Cursor самостоятельно пишет необходимые capture/validation scripts и тесты,
читает первичные тексты, составляет assumption cards и предложение R2. Scripts
фиксируют и проверяют evidence; интерпретацию пишет агент. Не выдавать простой
file-copy или извлечение PDF за автоматическое научное прочтение.

## Разрешённые три блока

1. **История.** Проверить SHA-256 небольших доступных snapshots/logs/JSON и их
   locator-to-observation mappings. Отдельно оценить округление accuracy,
   незавершённый MLP sweep, правое плечо, convergence, отсутствие итогового
   checkpoint, конфликт metadata 768/4096, row-order/cache и старый scope.
   Большие файлы разрешено перечислять и читать только заголовки; их содержимое
   не сканировать и не хешировать. Неустановленные свойства остаются not_assessed.
2. **Литература.** Все L01–L08 из исходного registry получают full-text карточку
   либо документированную причину недоступности. Максимум четыре дополнительных
   первичных источника, каждый только для конкретного пробела. Указывать версию,
   retrieval date/hash, локаторы, модель/данные/loss, изменяемые и фиксированные
   оси, определение интерполяции, допущения, тип результата и границы переноса.
   Сравнить условия tree/GBDT работ; нерешённое противоречие можно оставить
   нерешённым. Abstract-only не становится полнотекстовым review.
3. **Предложение R2, без запуска.** Min-norm/ridge и random features: явный
   teacher, нормировки и ridge objective, вложенные признаки, отдельные seeds
   data/noise/features, p/n, splits и test exposure, SNR/noise, solver/rcond/rank/
   residual/norm/spectrum, estimand, uncertainty и bias–variance по independent
   draws на общих evaluation points. Для механизмов — вмешательство,
   предсказание, фальсификатор и inconclusive outcome. Появление пика не требуется.

## Ресурсы и остановки

- До 120 минут работы Cursor, включая подготовку, чтение, реализацию и ревью.
  Вести preparation log; не обнулять этот бюджет при запуске новой сессии.
- Один dispatcher; runner до 900 секунд на attempt, суммарно до 1800 секунд,
  максимум 2 attempts. Сбои и исключения сохраняются.
- Только открытые первичные страницы и разрешённые версии текстов; не более
  200 MiB загрузок, 25 MiB на документ, 2 retrieval attempts на источник.
  Стартовые L01–L08 плюс не более четырёх дополнений; не более 48 HTTP requests
  включая retries, но не отдельные redirects транспортной библиотеки.
- Не более 2 GiB новых файлов всего R1, включая intake, snapshots и attempts.
  Старые файлы не входят в расход; только метаданные больших исторических матриц.
- Новое обучение, GPU, новые эмбеддинги, загрузки датасетов, paid API и внешние
  model-provider вызовы из scripts: **0**. Работа Grok внутри Cursor — выбранный
  пользователем harness, а не разрешение запустить отдельный API/provider.

Недоступный источник получает disposition, а зависимое предложение — limitation
или blocked readiness. Это не требует бесконечных retries. При исчерпании общего
бюджета, integrity failure или необходимости изменить научный вопрос сохранить
пакет и вернуть конкретное решение Codex/человеку. Недоступность источника сама
по себе не мешает операционно закрыть полный аудит с честными dispositions.

## Активация без повторного согласования

Исходники R1 ещё не реализованы, поэтому machine plan честно остаётся draft,
`execution_authorized=false`, а `preparation_authorized=true`. Научное решение
уже принято этим документом; false сейчас означает незавершённый preflight.
Это **не** запрос нового разрешения после написания кода.

Cursor уполномочен самостоятельно:

1. Выполнить подготовку по HANDOFF и TASK-CONTRACT, записать уже прочитанные
   результаты/источники, реализовать scripts/tests и фактические source inputs.
2. Сохранить неизменными scope, budgets, task IDs/выходы, научные критерии и
   decision digest. Дополнять inputs реальными файлами и выбирать внутреннюю
   архитектуру scripts в этих пределах; пустые/фиктивные outputs недопустимы.
3. Установить machine `status=frozen` и выполнить `validate-plan R1`, пока
   execution flag ещё false. После PASS поменять **только R1** на
   `execution_authorized=true`, ещё раз проверить digest/план и repository checks.
4. Выполнить run/verify, REPORT, bound operational review, close, архив и handoff.
   Дополнительная научная подпись для этих routine steps не нужна.

`check_repository.py` и runner gates не ослаблять ради draft-плана. R0 не
перезапускать. R2 активировать только после его собственного preflight и review
субагентом, без обязательного нового решения Codex. Если нет критической
эскалации, продолжить цепочку по решению 0003. Claims продвигать только через
bound substantive review отдельного субагента, не автоматически из stage PASS.
