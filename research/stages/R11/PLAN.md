# R11 — причинный контроль ускорения через расписание learning rate

Статус: draft до отдельного design review и заморозки machine plan.
Автор реализации: `/root/catboost_study`; reviewer не должен быть этим автором.
Протокол: `inputs/protocol.json`. Вычисления этого протокола до review не запускались.

## Вопрос и научный смысл

Достаточно ли заранее заданного изменения learning rate, чтобы изменить
скорость падения train LogLoss CatBoost около известной границы при одинаковой
сумме learning rate? Это положительный причинный контроль для интерпретации
детектора ускорения. Даже воспроизводимое ускорение этого вида не означает
естественный новый механизм бустинга или double descent.
Причинный контраст относится ко всему расписанию: предыстория плеч до границы
различается. Он не изолирует мгновенный скачок при идентичных первых 128 деревьях.

Исследование не выбирает конфигурацию по наличию ускорения. Синтетическая
калибровка R10 не предоставляет автоматически допустимых p-value для реальных
траекторий CatBoost: её применение здесь может быть только описательным.

## Дизайн, единица повторения и данные

Два заранее заданных окружения: `make_classification` из sklearn (768 строк,
10 признаков, 5 информативных, 0 redundant, `flip_y=.08`, `class_sep=.8`;
остальные параметры явно заданы в исходнике) и встроенный Wisconsin Breast
Cancer (569 строк). Никакого скачивания. На синтетике каждый seed генерирует
новую выборку. Breast Cancer повторяет разбиение и модель условно на одном
фиксированном корпусе, а не создаёт независимые корпуса.

Seeds: 12001–12012, ранее не использованные здесь. Каналы: data=seed,
split=seed+100000, model=seed+200000. Модель использует один и тот же model seed
в двух продолжениях. Синтетика: стратифицированные 256/256/256; Breast Cancer:
стратифицированные 60/20/20 с целочисленным округлением sklearn. Сохраняются
полная матрица, метки, row order, split indices и их хеши. Preprocessing нет.
Парное сравнение использует идентичные строки, метки и seed внутри повтора.

Три плеча: constant (.11→.11), stepup (.02→.20), stepdown (.20→.02).
Два сегмента по 128 деревьев; сумма learning rate каждого плеча равна 28.16.
**Все** плечи, включая constant, обучаются через одинаковые два `fit` с
`init_model`, чтобы граница продолжения не совпала только с вмешательством.
Параметры CatBoost фиксированы: CPU, 4 потока, depth 4, L2 3, bootstrap No,
random_strength 1, Logloss, boost_from_average true на первом сегменте и false
на continuation (CatBoost запрещает true вместе с init_model), use_best_model false,
border_count 254, leaf_estimation_iterations 1, boosting_type Plain.

Единица повторения — один seed (генерация/разбиение/модель), а не отдельная
итерация. 2×12×3=72 модели, каждая из двух последовательных `fit`. Одновременно
работает одна модель. Выборки validation/test ничего не выбирают: все плечи и
контрасты заданы до открытия результатов; test используется только для оценки.

## Предсказания и фальсификаторы

Первичная статистика фиксирована на границе 128: OLS скорости снижения
LogLoss на 32 точках до (`loss[97:129]`) и после (`loss[128:160]`), с общей
граничной точкой. Gain = velocity_after − velocity_before. Затем парная разность
gain(schedule) − gain(constant). Ни граница, ни окно не сканируются.

- P1: stepup−constant > 0 отдельно в каждом окружении.
- P2: stepdown−constant < 0 отдельно в каждом окружении.
- P3: 72 полные траектории и идентичные данные внутри пар; применение test для
  выбора сетки отсутствует, double_descent_declared=false.

Для четырёх первичных контрастов пишутся среднее, SE, обычный двухсторонний
95% Student-t интервал и Bonferroni-интервал с общим уровнем 95% (каждый
98.75%). Supported требует, чтобы **скорректированный** интервал лежал по
предсказанную сторону нуля; refuted — по противоположную; иначе inconclusive.
Интервалы предполагают независимые парные повторы и приемлемость t-приближения;
12 повторов не доказывают точность этого приближения. Отрицательный исход не
меняет сетку и не препятствует операционному завершению.

Траектории validation/test, errors, minimum и q10 margin, gradient RMS и доля
абсолютного градиента у верхних 10% объектов являются описательными
измерениями. Они не входят в первичную семью тестов и не выбирают claim.

Дополнительный заранее заданный диагностический контраст повторяет OLS на
тех же точках, заменяя номер дерева накопленной предписанной суммой learning
rate (t=0 имеет сумму 0). Четыре парных разности по этому clock получают
отдельную семью Bonferroni-интервалов 95%, без предсказанного знака и без
статуса supported/refuted. Снижение ускорения при смене clock само по себе не
доказывает механизм: расписание меняет путь градиента и выбранные разбиения.

## Артефакты, критерии выхода и остановки

`cells.jsonl`: все метрики всех итераций 0…256, точные ошибки, хеши данных и
raw predictions, seed и конфигурация; `predictions.npz`: raw margins для каждой
строки каждого split каждой итерации; `data.npz`: данные/метки/индексы;
`models/*.cbm` и `models.json`: полные модели и их хеши;
`analysis.json`: заранее заданные парные контрасты и статусы;
`environment.json`: версии библиотек и runtime. t=0 — fitted model bias,
проверенный относительно logit доли положительного класса train.
Малые fitting smoke checks (balanced/unbalanced bias и сохранение prefix)
включаются только флагом `run_unit_checks.py --model-smoke` в research task;
обычный `check_repository.py` пропускает их и не запускает обучение.

- C1: ровно 72 ячейки, все seed/плечи/окружения, 256 деревьев, 257 временных
  точек; finite raw predictions и полные сохранённые модели.
- C2: входные data hashes совпадают внутри каждого парного сравнения;
  raw staged prediction на последней итерации совпадает с model.predict.
- C3: четыре первичных контраста с полными значениями 12 пар и обоими
  интервалами и четыре диагностических контраста по clock накопленного LR;
  отрицательные/inconclusive исходы сохранены.
- C4: GPU/API/download равны нулю; нет объявления double descent или нового
  естественного механизма; синтетические p-values не объявлены переносимыми.

Бюджет: ≤1800 с на attempt, ≤3600 с суммарно, максимум 2 attempts; task timeout
≤1700 с; ≤1 GiB новых выходов; GPU 0, платные API 0, скачивания 0. Общие лимиты
исследования не обнуляются. Остановка — ровно один проход сетки либо явный
технический сбой/таймаут. Сбой сохраняется; retry имеет новый attempt.

## Исключения и пределы

Техническая поправка после attempt `20261107T192904-5420604589`: обучение и
каждый вызов staged_predict/predict ограничиваются явным thread_count<=4.
В первой попытке inference имел default -1, поэтому ресурсная гарантия не
была обеспечена. Попытка сохраняется с revise; retry повторяет неизменную
научную matrix и seed, не увеличивает n и не выбирает лучшую форму кривой.

Нет поиска естественного ускорения перебором настроек. Нет корпуса Qwen,
широких MLP, новых таблиц или XGBoost/LightGBM. Положительный контроль не
устанавливает универсальный механизм, перенос на другие learning-rate
расписания или double descent. Число деревьев не выравнивает ёмкость с MLP.
