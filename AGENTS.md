# Исследование двойного спуска

## Действующий контракт

Начни с `README.md`, `research/STATE.md`, `docs/research-program.md` и
`docs/automation.md`. Машинное состояние проверяй через
`uv run python scripts/research.py status` и `next`.
`objective.md`, `docs/plan/` и протоколы 4/6 ноября — история, не очередь запуска.

Человек и Codex отвечают за верхнеуровневый анализ/критику и критические
развилки. Cursor (Grok 4.7 Extra High, по выбору пользователя) с субагентами
сам ставит детальный дизайн внутри общей программы, реализует, исполняет,
анализирует, рецензирует этапы/выводы и пишет статью. Отдельный reviewer
субагент не должен быть автором оцениваемой реализации или вывода.
Повторное разрешение Codex на каждый stage, план или claim не нужно.
Смена модели в настройках Cursor не автоматизируется этим репозиторием.

R0 закрыт. Для R1–R7 действует [единая авторизация](docs/decisions/0003-cursor-autonomous-research.md).
`preparation_authorized=true` разрешает Cursor самостоятельно завершить
план/реализацию, получить review субагента, заморозить и проверить inputs,
затем самому активировать execution текущего stage. Начальный execution=false
означает незавершённый preflight, не ожидание нового разрешения Codex.
Зависимости, evidence integrity и общие бюджеты обязательны.
Не пытайся получить нужную форму кривой перебором данных и настроек.

## Инварианты

- До вычисления: вопрос, предсказания, фальсификаторы, сетка, seed, единица
  повторения, бюджеты, остановки, критерии выхода и исключения в плане этапа.
  Машинный PLAN.json дополняется научным PLAN.md. Discovery и confirmation
  имеют разные планы и данные; адаптация сетки по test запрещена.
- Один этап и один процесс диспетчеризации за раз. Никаких фоновых запусков
  без записанного идентификатора. Сбой сохраняется, не удаляется. Новый запуск
  получает новый attempt; удачный task не становится пропущенным наблюдением.
- Каждый численный вывод связан с run/task ID, входными хешами, source snapshot,
  `uv.lock`, seed, конфигурацией, сырыми метриками, логами и отчётом.
  Указание commit без dirty/untracked исходников недостаточно.
- Нулевой exit code не означает научной валидности. `close` закрывает операционный
  этап; `scientific_validity=not_assessed` не означает, что Cursor запрещено
  анализировать evidence или принимать локальные team-reviewed выводы.
  Две роли одного агента не являются независимой репликацией или рецензией.
- Научный claim в статье требует записи `research/claims.json` с точными
  артефактами, scope, ограничениями и bound review отдельного Cursor субагента
  по общей авторизации либо реальным human/Codex review. Cursor lane использует
  `assessment=evidence_supported`, `review_status=cursor_team_reviewed`.
  Самостоятельная подпись автора не заменяет reviewer. Human approval не выдумывать.
- Новые результаты пишутся в `artifacts/research/`, не в `result/`. Старые
  `.research/double-descent*` не открывать на запись. Старый domain pack про
  текст не описывает новое межмодельное исследование.
- Не читать `.env` в вывод, не включать секреты в snapshots, отчёты или команды.
  Подключения к API/загрузки данных/ресурсные бюджеты фиксировать до запуска.
- `C:/projects/llm-semantic-afterlife` — только read-only пример. Ничего там
  не менять. `EpistemeOS-0.2.0/` — зафиксированный исходный dependency snapshot;
  не модифицировать ради обхода gates.

## Завершение и возобновление

При обычном отрицательном/inconclusive исходе, техническом retry или выборе
деталей в пределах программы Cursor продолжает сам. Критическую эскалацию
делать по решению 0003: содержательная неожиданность после проверки, развилка
основной программы, центральная integrity проблема или выход за общий мандат.
Готовить evidence packet; независимые разрешённые ветки можно продолжать.

Перед передачей управления: `verify`, REPORT, заполненное операционное REVIEW,
`close`, затем `research/STATE.md` с точной следующей командой и нерешёнными
вопросами. После прерывания сначала `status`/`verify`; не считать незавершённый
attempt успешным и не снимать lock без проверки PID. Экспорт архива и проверка
восстановления описаны в `docs/automation.md`.

Проверки: `uv sync --frozen`, `uv run python scripts/check_repository.py --output
checks.json`. CI работает без платных API и обучения моделей. Не коммить
вычисленные результаты как подтверждение заранее желаемой гипотезы.
